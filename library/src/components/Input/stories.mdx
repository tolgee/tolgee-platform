# Input

<Upstream docs="react-text-field" />

Material UI's `TextField` underneath, but **Tolgee does not use it the way Material UI documents
it.** The upstream page shows a label that floats into the border, and a `standard` variant that is
only an underline. Neither is the shape this product uses.

## The Tolgee field

<Canvas of={InputStories.TheStandard} />

Three rules, and they hold for every kind of field — text, select, date:

1. **The label sits above the field**, as its own element. It never floats into the border and the
   field is never left with only an underline.
2. **The field is an outlined box.** One border, all the way around.
3. **The row reserves 64px**, so a validation message can appear without pushing the rest of the
   form down.

The placeholder goes inside the box and says what to type — _Task_, _MM/DD/YYYY_ — while the label
above says what the field is. They are not alternatives to each other.

Measured on the rendered page, so these are the numbers the product actually shows:

|                     | Value                             |
| ------------------- | --------------------------------- |
| label               | 14px, regular, `text.secondary`   |
| gap under the label | 4px                               |
| field text          | 16px (`body1`)                    |
| field height        | 40px (`size="small"`), 4px corner |
| row reserve         | 64px                              |

The label is regular weight rather than medium **because the declaration that asked for medium is
invalid** — see Findings. Fixing it will make every label in the product heavier, which is a visible
change worth deciding on rather than slipping in.

<Callout title="Why the label is above and not inside">
  A floating label moves when the field is filled and shrinks to a size that is
  hard to read. Above the field it stays put, stays the same size, and every
  label in a form starts at the same x-position — which is what makes a column
  of fields scannable.
</Callout>

## One model, and two that are not options

<Canvas of={InputStories.TheOnlyModel} />

**The product has one field.** The other two shapes exist in the codebase, and both are defects
rather than choices:

- **A floating label** comes from importing `TextField` straight from `@mui/material`. The label
  moves and shrinks when the field fills, and it does not line up with the labels above it.
- **An underline** comes from `variant="standard"`. It has no box, so in a form beside the others it
  reads as a different kind of control.

Neither is a variant to pick between. If a screen shows one, it is something to fix — they are
counted and located on **Findings**.

## Messages under the field

<Canvas of={InputStories.WithAMessage} />

`helperText` carries the hint and switches to the error when the field is rejected. It is the same
line either way, and the 64px reserve is what keeps the form still when it appears.

## Long text

<Canvas of={InputStories.Multiline} />

`multiline` with `minRows` — give it a starting height rather than one line, or the form jumps as
soon as anyone types.

## Search

<Canvas of={InputStories.Search} />

A search field is this component with a magnifier in front, a clear button behind and a debounce.
It has no label above, because the magnifier and the placeholder already say what it is:

```
<TextField
  placeholder={t('standard_search_label')}
  InputProps={{
    startAdornment: <InputAdornment position="start"><SearchSm /></InputAdornment>,
    endAdornment: value && (
      <InputAdornment position="end">
        <IconButton size="small" onClick={clear}><XClose /></IconButton>
      </InputAdornment>
    ),
  }}
/>
```

That is `tg.component/common/form/fields/SearchField`, which also debounces by 500ms. Use it rather
than assembling the adornments again.

## How to get the standard

| You need                 | Use                                           |
| ------------------------ | --------------------------------------------- |
| a field in a formik form | `tg.component/common/form/fields/TextField`   |
| a field outside a form   | `tg.component/common/TextField`               |
| a select                 | `tg.component/common/Select`                  |
| a search box             | `tg.component/common/form/fields/SearchField` |

**Not `TextField` from `@mui/material`.** It gives you the floating label and none of the rules
above. 63 of the 100 fields go through the wrapper; the other 37 are on the Inventory page, with
the 22 that come out the wrong shape marked.

## Don't

- **Don't use `variant="standard"`.** An underline is not this product's field.
- **Don't pass `label` to a Material UI `TextField`.** That is the floating label.
- **Don't use a placeholder instead of a label.** It disappears exactly when it is needed.
- **Don't set a width on the field.** The form's grid decides.

## Where the styling lives

`MuiInputBase` in `library/src/theme/getTheme.ts` holds one rule — the background of an outlined
input. Everything that makes the field a Tolgee field lives in
`webapp/src/component/common/TextField.tsx` instead, which is the reason it can be bypassed. See
**Foundations → Component styles**.
