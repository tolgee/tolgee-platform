# Input — findings

Measured by hand on 2026-08-18 across 100 call sites. A work list: **done when it is empty.**

## One field, three shapes

<Canvas of={InputStories.FindingThreeShapes} />

The product's shape is the label above an outlined box. Counting all 100 call sites by where their
`TextField` is imported from:

| Shape                        | Call sites | How it happens                                              |
| ---------------------------- | ---------- | ----------------------------------------------------------- |
| **label above the field**    | **74**     | through `common/TextField` or the formik field              |
| underline, no box            | 21         | `variant="standard"` passed at the call site                |
| label floating in the border | 6          | Material UI's `TextField` imported directly, with a `label` |

The remaining call sites have no label at all, which is right for search boxes and table cells.

<Callout title="Suggested fix">
  Take the 21 underlined fields to the standard, then the 6 floating ones — the
  second group also has to move off the direct Material UI import.
</Callout>

## The wrapper states the standard but does not hold it

<Canvas of={InputStories.FindingOverridable} />

`common/TextField` sets `variant="outlined"` and `size="small"` — and then spreads the caller's
props after them:

```
<MUITextField ref={ref} variant="outlined" size="small" sx={…} {...otherProps} />
```

So any caller can walk over the decision with one prop, and **eleven formik fields do exactly
that**, rendering as `standard` through a wrapper whose whole point was to stop that.

<Callout title="Suggested fix">
  Spread `otherProps` first and set `variant` after it, so the wrapper's own
  decisions win. Then fix the eleven callers that were relying on the override.
</Callout>

## A typo nobody sees, in two places

`tg.component/common/TextField` styles its label with:

```
font-size: 14px;
font-weight: 500px;
```

`500px` is not a font weight. The browser drops the declaration, so the label renders at the default
400 rather than the intended medium.

It does not stop at TextField. `common/Select` imports the very same `StyledInputLabel`, and both
wrappers are in turn wrapped by their formik versions — so the broken label reaches **66 files**:

| Through                 | Files |
| ----------------------- | ----- |
| `common/TextField`      | 15    |
| `form/fields/TextField` | 39    |
| `common/Select`         | 8     |
| `form/fields/Select`    | 4     |

`common/Switch` has its own copy of the same mistake, `font-weight: 400px`. That one happens to be
invisible — the fallback is 400 anyway — which is exactly why it survived.

<Callout title="Suggested fix">
  `font-weight: 500` in the shared label and `400` in Switch. Expect the labels
  to change weight where they should have been medium all along.
</Callout>

## Five search fields, one of them shared

`common/form/fields/SearchField` is the real one: magnifier, clear button, 500ms debounce. Four
others exist beside it.

| Field                     | Built on                                        |
| ------------------------- | ----------------------------------------------- |
| `SearchField`             | `TextField` — the shared one                    |
| `SecondaryBarSearchField` | wraps `SearchField` ✓                           |
| `HeaderSearchField`       | its own `TextField`, adornments assembled again |
| `FlagSearchField`         | its own                                         |
| `TranslationsSearchField` | its own                                         |

`HeaderSearchField` repeats the adornments, the clear button and the icon sizes that `SearchField`
already has, and the two now differ in ways nobody chose.

<Callout title="Suggested fix">
  Fold `HeaderSearchField` onto `SearchField` the way the secondary bar already
  does, and check whether the other two can follow.
</Callout>

## Two search fields import icons from the package

`SearchField` and `HeaderSearchField` both do:

```
import { SearchSm, XClose } from '@untitled-ui/icons-react';
```

**Foundations → Icons** asks for the library instead. These two are the closest violations to hand
because they sit in shared components, where the next person copies from.

<Callout title="Suggested fix">
  Import from `@tginternal/library/icons`, and add the eslint rule that makes
  the page's own instruction enforceable.
</Callout>

## Not wrong

75 of the 100 pass a `label`, and the 26 placeholders sit where the label is carried by the layout.
`helperText` doubles as the error message on all 8 error states rather than adding a second line, so
the form never jumps.
