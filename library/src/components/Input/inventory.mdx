component it names, so the picture is what ships rather than an impression of it.

Read it as a checklist: fields that look alike and are built differently, or look different and mean
the same thing, are the ones to settle.

## What is not on this page

`Editor`, `EditorJson` and `EditorHandlebars` — the translation editor is CodeMirror 6 and shares

## The advanced search overflows on its own

The translations search is a CodeMirror editor, and long queries are handled by this, in
`searchFieldStyles.ts`:

```
& .cm-scroller {
  overflow-x: hidden;
}
```

The editor never wraps — there is no `lineWrapping` extension and a transaction filter forces the
document to stay one line — so a long query runs past the right edge and is clipped. The caret stays
visible because CodeMirror scrolls to it programmatically, but **the user cannot scroll the field**:
no wheel, no drag, no way to look at the start of a query while the caret is at the end.

A native `<input>`, which is what every other field here contains, does this without being asked.
Material UI does not solve overflow — it simply does not get in the way of the browser.

<Callout title="It can be built from Material UI, and the codebase already knows how">
  `TextField` accepts `InputProps={{ inputComponent }}`, which replaces the
  inner input while keeping the border, the hover and focus rings, the adornment
  slots, the sizes, the disabled and error states and the theme wiring. The
  filter beside it already uses that hook to pass a `div` — so the mechanism is
  in the codebase, just used for the wrong purpose. The search would keep its
  CodeMirror area as the `inputComponent` and stop reimplementing the shell
  around it.
</Callout>

## The shape of the problem

Counted from the samples above, one row of the translations header holds **three unrelated
mechanisms**: a CodeMirror editor styled as a field, a read-only text field standing in for a
select, and an icon button. None of them is the component the rest of the product uses for the same
job.

<Callout title="Where to start">
  The five search fields are the cheapest win — four of them want to be one. The
  two fake fields are the most valuable, because they are the ones a screen
  reader gets wrong.
</Callout>
